# 環境の確認手順

現在の環境(どの環境デッキが使われ、勝っているか)を確認する手順と、環境情報サイトの参照方針を定める。用語は [CONTEXT.md](../../CONTEXT.md)「環境と大会」に従う。

作業前に[公式サイト利用上の注意](site-usage-notes.md)を読むこと。デッキコードからデッキ内容を読む手順は[公式デッキ構築ツールの使い方](deck-tool.md)の手順 1、カードの確認は[カード情報の確認手順](card-lookup.md)に従う。確認した結果は[環境スナップショット](metagame-snapshot.md)に記録する。

最終確認日: 2026-09-13。各サイトのページ構成と利用条件は、この日に閲覧して確認した観測結果であり、サイトが保証する仕様ではない。構成が変わっていたら、実際のページを開いて確認し、この手順書を直す。

## 情報源の役割分担

環境の確認では、情報の種類ごとに参照先を分ける。

| 知りたいこと | 参照先 | 扱い |
| --- | --- | --- |
| どの環境デッキが多く、勝っているか(傾向、Tier) | 環境情報サイト(ポケカブック、ポケカ飯) | 要約とリンクにとどめる。内容を転載しない |
| 大会で結果を残したデッキの 60 枚 | 公式のイベント結果、環境情報サイトに載るデッキコード | デッキコード経由でデッキ構築ツールから読む。デッキ内容をリポジトリに保存しない |
| カードの効果、数値、スタンダードで使えるか | カード検索 | [カード情報の確認手順](card-lookup.md)の 3 点確認 |

環境情報サイトはデッキの分布を知るためだけに使う。カードの事実を環境情報サイトの記述で済ませない。

## 参照先

### 公式: イベント結果(プレイヤーズクラブ)

- イベント結果一覧: https://players.pokemon-card.com/event/result/list
- 各イベントの結果ページ: `https://players.pokemon-card.com/event/detail/{イベント ID}/result`

2026-09-13 に確認した構成。

- 一覧は新しい順で、チャンピオンズリーグ、シティリーグ、ポケモンジャパンチャンピオンシップスの各リーグが混在する。絞り込みの機能は無く、1 ページ 20 件で 140 ページあった
- 各結果ページには、順位、獲得ポイント、ユーザー名、エリアと、「デッキをみる」のリンクが載る。リンク先は `https://www.pokemon-card.com/deck/confirm.html/deckID/{デッキコード}` で、公式のデッキコードにそのまま飛ぶ。シティリーグの結果ページでは 1 位から 5 位(同順位を含む 8 名)ぶんのデッキコードを確認した
- ページは JavaScript で描画される。HTML を取得するだけのツールでは内容が読めないため、ブラウザで開く
- チャンピオンズリーグの優勝者インタビュー(例: https://www.pokemon-card.com/info/005415.html )にも、各リーグの優勝デッキのデッキコードが載る

使い方。

- 環境デッキの内容を公式のデッキから確認したいときの起点にする。目当ての大会の結果ページを 1 つ開き、デッキコードを控えて、デッキ構築ツールで読む
- **一覧を機械的にたどらない。** 140 ページの巡回や、全結果ページの一括取得はしない。開くのは、確認に必要な結果ページだけにする
- シティリーグはシーズン制で、シーズンの外(2026 年は 6 月から 8 月)は新しい結果が出ない。この期間の直近の公式結果はポケモンジャパンチャンピオンシップスの結果になり、環境名が変わっていることがある(2026-09-13 時点の一覧の先頭は 6 月 7 日開催の PJCS で、環境名はその後の拡張パック発売で変わっていた)

### ポケカブック(https://pokecabook.com/)

- 環境デッキランキング(Tier 表): https://pokecabook.com/archives/26148 。更新日と環境名が本文にあり、Tier ごとの環境デッキ名と、Tier が動いた理由の解説が載る。運営者はチャンピオンズリーグ入賞などの実績を持つプレイヤーである旨の記載がある
- シティリーグのベスト 16 まとめ(例: https://pokecabook.com/archives/319861 )。大会ごとに順位とデッキコード、公式の結果ページへのリンクが並ぶ(1 記事に 450 個のデッキコードを確認)
- カテゴリ: チャンピオンズリーグ(https://pokecabook.com/archives/category/tournament/champions )、シティリーグ(https://pokecabook.com/archives/category/tournament/city-league )、ジムバトル(https://pokecabook.com/archives/category/tournament/jim-battle )

使い方。

- 「今どのデッキが強いか」の傾向は、Tier 表の更新日と環境名を添えて要約する
- 公式のイベント結果から目当ての大会を探しにくいときは、ベスト 16 まとめから公式の結果ページへたどる
- **HTML を取得するだけのツールは 403 で拒否される**(2026-09-13 に WebFetch で確認)。ブラウザで開く

### ポケカ飯(https://pokekameshi.com/)

- Tier 表: https://pokekameshi.com/strongestdeck-tire/ 。更新日が本文にあり、Tier ごとの環境デッキ名と、各環境デッキの「参考デッキレシピ」として大会名、成績、デッキコードが載る
- 「インプットデータについて」の節に集計の根拠が書かれている。シティリーグのシーズン中は結果から各デッキの獲得ポイントを集計し、シーズンの外(オフシーズン)は規模の大きい自主大会の結果を独自に集計する、という説明(2026-09-13 確認)
- シティリーグ結果まとめ: https://pokekameshi.com/category/cityleague/ 。大型大会(PJCS、WCS)の上位デッキまとめもあり、デッキコード付き(WCS2026 の記事で 31 個を確認)

使い方。

- 傾向の要約に加えて、代表デッキの候補(大会で結果を残したデッキのデッキコード)を得る
- Tier 表の相性表は海外のデータ(Limitless TCG)が出典と書かれている。日本の環境の根拠としては使わない

### 評価して採用しなかったサイト

- カードラッシュメディアの Tier 表(https://cardrush.media/pokemon/articles/981 )。更新日はあるが、デッキコードが無く、集計の根拠が「参考評価」とだけ書かれている(2026-09-13 確認)。傾向の裏取りが必要なときの第 3 の意見にとどめ、参照先には含めない
- Limitless TCG(https://limitlesstcg.com/tournaments/jp )。日本のシティリーグの結果を載せるが、プレイヤーズクラブ由来のデータで、カード名は英語、デッキコードは無い(2026-09-13 確認)。公式のイベント結果で足りる

## 利用条件と配慮

各サイトの利用条件(2026-09-13 確認)。

| サイト | 利用条件で確認できたこと | robots.txt |
| --- | --- | --- |
| プレイヤーズクラブ | 利用規約(https://www.pokemon-card.com/event/players_policy/ )に、コンテンツをサービス外で利用できない旨(第 7 条)と、大会参加者のデッキレシピなどを結果の公表に使う旨(第 6 条)。自動取得の条項は無い。フッターに著作権の帰属の記載 | Cloudflare 管理の記述があり、ClaudeBot や GPTBot などの AI クローラーを名指しで拒否し、Content-Signal に「ai-train=no, use=reference」とある |
| ポケカブック | プライバシーポリシー(https://pokecabook.com/privacy-policy )に免責事項。転載可否の明文は見つからなかった。個人のファンブログである旨の記載 | サイト内検索の URL だけ拒否 |
| ポケカ飯 | 専用の規約ページは見つからなかった。フッターに「サイト独自の内容に関する著作権」の表記と、個人のファンサイトである旨の記載 | WordPress の管理画面だけ拒否 |

この観測に基づき、次のように振る舞う。

- **転載しない。** Tier 表、順位表、解説文をリポジトリに書き写さない。傾向は自分の言葉で要約し、参照 URL と確認日を添える。環境スナップショットに書くのは、環境デッキ名、デッキコード、カード ID、出典 URL、確認日といった識別子と事実に限る
- **デッキ内容を保存しない。** 60 枚の内容はデッキコード経由で都度読む。公式のイベント結果もサービス外での利用が制限されているため、結果ページの内容を書き写さない
- **自動取得をしない。** クローラーや一括取得のスクリプトを書かない。エージェントがブラウザで必要なページを開いて読む範囲にとどめる。プレイヤーズクラブは AI クローラーを拒否しているので、なおさら一覧の巡回をしない
- **開くページを絞る。** 1 回の確認で開くのは、Tier 表 1〜2 ページ、目当ての結果ページ、確認する代表デッキのデッキ表示ページまでにする。同じページを繰り返し開かない
- **リンクはテキストリンクで書く。** 画像の埋め込みや引用をしない

## 鮮度の扱い

- 「現在の環境」は環境名で区切る。最新の拡張パックの発売日は公式の商品情報ページ(https://www.pokemon-card.com/products/ )で確認する
- Tier 表は、更新日が最新の拡張パックの発売日より新しいものだけを「現在の環境」の根拠にする。発売日より古い Tier 表は前の環境のものとして扱う
- 環境スナップショットは、次の拡張パックが発売されたら古いとみなし、発売から 2 週間をめどに更新する。更新までの間に環境に触れるときは、スナップショットが前の環境のものであることを添える
- 会話で環境に触れるときは、必ず確認日と参照 URL を添える。「環境で強い」とだけ書かない

## 環境を確認する手順

ユーザーの相談で環境に触れる必要が出たときの手順。

1. 環境スナップショットの環境名と確認日を見る。商品情報ページで最新の拡張パックの発売日を確認し、スナップショットが現在の環境のものか判定する
2. 現在の環境のものなら、スナップショットの環境デッキと通称の対応で足りる範囲はそれを使う。会話にはスナップショットの確認日と出典 URL を添える
3. スナップショットに無い環境デッキや、より新しい傾向が必要なら、ポケカブックとポケカ飯の Tier 表を開いて要約する。両サイトの評価が違うときは、両方の見立てを更新日付きで並べ、どちらかに寄せない
4. 特定の環境デッキの内容が必要なら、代表デッキのデッキコードをデッキ構築ツールで読む(deck-tool.md 手順 1)。そこに出てきたカードの効果に触れるときは 3 点確認を行う
5. スナップショットが古ければ、下記の更新手順で作り直す

## 環境スナップショットの更新手順

1. 商品情報ページで最新の拡張パックの商品名と発売日を確認し、環境名を決める
2. ポケカブックとポケカ飯の Tier 表を開き、更新日と、Tier1 と Tier2 の環境デッキ名を読む。両サイトの Tier1〜2 の和集合をスナップショットの対象にする。Tier3 以下は名前と Tier だけを一覧に載せ、代表デッキは付けない
3. 対象の環境デッキごとに代表デッキを 1 つ選ぶ。選ぶ順は、現在の環境で開かれた公式のイベント結果に載るデッキ、次にポケカ飯の Tier 表の参考デッキレシピ(自主大会の結果)。出典の URL、大会名、成績を控える
4. 代表デッキをデッキ構築ツールで読み、主軸カードのカード名とカード ID を控える。主軸カードはカード検索で 3 点確認し、詳細ページの URL と確認日を記録する
5. 対象の代表デッキ全体で半数以上に入っているカードを「広く採用されているカード」として集計し、カード名とカード ID を記録する。枚数や個々のデッキの内容は書かない
6. 通称の対応表を更新する。環境情報サイトの本文やユーザーの発言で観測した通称と、それが指すカード名を対応付ける。同じ通称で呼べるカードがスタンダードに複数あるときは、カード検索の結果からその旨を注記する
7. 確認日と更新履歴を書く

## 通称の解決手順

ユーザーがカードや環境デッキを通称で呼んだときの手順。

1. 環境スナップショットの通称の対応表を引く。対応があれば、そのカード名として扱い、返答の中でカード名を一度書いて認識を揃える(例: 「ニャースex ですね」)。確認の質問で会話を止めない
2. 対応表に注記(同じ通称で呼べるカードが複数ある)があるときは、文脈で判断する。環境デッキ名として使われていればその環境デッキの主軸カード、ワザや特性の話なら 3 点確認で該当するカードを特定する。判断がつかなければユーザーに確認する
3. 対応表に無い通称は、カード検索で部分一致検索し(card-lookup.md 手順 1)、ヒットしたカード名から候補を挙げる。スタンダードで使えるカードが 1 つに絞れればそれとして扱い、複数あればユーザーに確認する
4. 解決したカードについてカードの事実(効果、数値、使用可否)に触れるときは、通称の解決とは別に 3 点確認を行う

## デッキ構築とデッキ診断で環境を参照する場面

### デッキ構築(pokemon-tcg-build-deck)

- **要望の聞き取り**: 通称で呼ばれたカードや環境デッキを、通称の解決手順でカード名に直す
- **候補カードの確認**: ユーザーが環境デッキを組みたいと言ったとき、または「今強いデッキ」を求めたときは、スナップショットの環境デッキと代表デッキを起点にする。代表デッキはデッキコードで読み、そのまま写すのではなく要望に合わせて組み直す。代表デッキの出典と確認日を伝える
- **60 枚の決定**: 環境デッキへの対策(メタカード)を提案するときは、対象の環境デッキがスナップショットか Tier 表にあることを確認し、確認日と出典を添える。スナップショットに無い環境デッキを「環境で多い」と言わない

### デッキ診断(#6 で設計するスキル)

- 診断対象のデッキがどの環境デッキに近いかの判断と、環境デッキへの相性の言及に使う。参照の具体的な場面は #6 の設計で決める
- 環境に関する言及は、スナップショットと環境情報サイトで確認できる範囲に限る。この文書の「鮮度の扱い」と「利用条件と配慮」は診断でも同じように適用する

## 会話での書き方

- 環境に触れる文には、確認日と参照 URL を添える。例: 「ポケカ飯の Tier 表(2026-09-07 更新、確認日 2026-09-13)ではドラパルトex が Tier1 です」
- Tier や順位は事実として書き、サイトの解説文を引き写さない。サイトの見立てであることが分かるように書く
- 環境の話に出てきたカードの効果や数値は、環境情報サイトの記述ではなくカード詳細ページで確認してから書く
