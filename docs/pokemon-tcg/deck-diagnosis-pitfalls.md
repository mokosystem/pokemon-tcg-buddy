# デッキ診断で起きる誤りの類型

デッキ診断と改良の助言で起きた、または起きうる誤りを類型として記録する。[pokemon-tcg-diagnose-deck スキル](../../.claude/skills/pokemon-tcg-diagnose-deck/SKILL.md)の手順の背景資料であり、受け入れ基準ではない。設計の理由は [docs/deck-diagnosis-design.md](../deck-diagnosis-design.md) にある。

出典は 2 つ。既存のデッキ診断サービスで開発責任者が観測した誤り(README「目的」と Issue 6「背景」に記載。サービス名と観測日の記録は無い)と、2026-09-14 の試験診断でエージェント自身が犯し、開発責任者の採点で退けられた誤り。後者の例は、題材のデッキの内容をリポジトリに保存しないため、判断に必要な事実だけを書く。

## 既存サービスで観測された類型

| 類型 | 内容 | 対策(スキルの手順) |
| --- | --- | --- |
| カードの事実に反する解説 | にげるエネルギーやタイプなど、カード詳細ページを見れば分かる事実と食い違う説明 | 手順 2。全カードの 3 点確認を、相談を聞く前に済ませる |
| デッキに入っていないカードを前提にした解説 | 60 枚に無いカードがあるものとして役割や動きを説明する | 手順 1〜2。60 枚を数え、確認記録の表にあるカードだけを前提にする |
| レギュレーションで使えないカードへの言及 | スタンダードで使えないカードを勧める。初心者が買っても対戦で使えない | 手順 7。入れるカードは 3 点確認を経る。登録時のレギュレーションチェックが最終の検証 |
| 環境に即していない説明 | 現在の環境に無いデッキを「多い」「強い」と言う | 手順 6。環境スナップショットで確認できる範囲に限り、確認日と URL を添える |
| 採用理由の説明が浅い | にげるエネルギー 0 の主軸ポケモンのデッキで、入れ替えのカードの採用理由を「にげるが重いから」と説明する。実際の理由は、相手のワザなどでにげるができなくなる状況への備え | 手順 3〜5。ユーザーに採用理由を聞き、役割表に備考として残す。理由を推測で埋めない |

## 試験診断でエージェントが犯した類型

| 類型 | 何が起きたか | 対策(スキルの手順) |
| --- | --- | --- |
| 役割の唯一の担い手を単体で評価して抜く | 手札干渉を担う唯一の 1 枚を「相手のサイドが減ってからしか使えず、今回の目的(序盤を速くする)と別」と評価して抜く提案をした。開発責任者は「これを抜くと相手の手札を減らす手段が無くなる」と退けた | 手順 5・7。役割表で唯一の担い手に印を付け、抜く提案ではなく「役割ごと手放すか」を問う |
| 主軸への道の必要カードを、サイドに置かれる確率だけで減らす | 2進化の主軸の中間進化のカードを 3 枚から 2 枚に減らす提案をした。根拠は「2 枚ともサイドに置かれる確率は 1 % 程度」。開発責任者は「手札に来たカードは山札から進化させるスタジアムで使えないので 3 枚でぎりぎり」と退けた。計算でも成立率が 4 ポイント下がった | 手順 4・7。主軸への道の必要カードは減らさない。手札に来る場合も含めて考える |
| 特性が重ならないカードの 2 枚目を保険と決めつける | たねポケモンのにげるエネルギーを 0 にする特性のポケモンを 2 枚から 1 枚に減らす提案をした。開発責任者は「序盤に場にいないと、にげるエネルギーの重いポケモンで始まったときにエネルギーを捨てて火力が落ちる」と退けた | 手順 5。序盤に場に必要な特性は、2 枚目が序盤の成立率を支えていると見る |
| ユーザーが試して外したカードを理屈で提案する | トラッシュから基本エネルギーをつけるグッズを、にげるで捨てたエネルギーを戻す用途で提案した。開発責任者は「以前試したが 10 試合で 1 回しか使えず、勝ちに絡まなかった」と退けた | 手順 3・7。相談を聞く段階で試したカードと結果を尋ね、試して外したカードは提案しない |
| 役割の一部を軽く見て系統ごと抜く | 1進化の系統(たねと進化先の 2 種)を、そろいにくいことを理由に丸ごと抜く提案をした。開発責任者は「たねのワザのグッズ封じは 2進化デッキの時間稼ぎとして重要で、1 枚でも残す」と退け、たねを 1 枚残す形にした | 手順 5・7。そろいにくさは役割を手放す理由にならない。1 枚で果たせる役割は 1 枚残す |
| 計算の締め切りを 1 つに固定して価値を隠す | 「3 番目の番までに攻撃できる確率」だけで枚数の増減を比べ、サポートを探す特性のポケモンを「ほとんど影響しない」と言った。開発責任者の問いで 2 番目の番の成立率を出すと、0 枚と 2 枚で 10 ポイント以上の差があった。3 番目の番までには別の道が追いつくため、差が消えていた | 「成立率を数字で示すとき」。複数の締め切りで出し、計算の範囲の外で価値を持つカードには数字が根拠にならないと添える |
| 効果の似たカードを同じ役割とみなす | 回復のカード 2 種のうち、デメリット無しで 150 回復するサポートを抜く候補に挙げ、もう 1 種(HP を全回復するがエネルギーが手札に戻るサポート)が残るからよいとした。開発責任者は「エネルギーが戻ると次の番につけ直す枠を使うので代替にならない」と退けた | 手順 2・5。効果の条件と副作用まで読み、役割表の備考に書く |

## 類型に共通すること

試験診断で退けられた提案は、いずれもカードの事実の誤りではなく、**カードテキストから組み立てた理屈が、そのデッキを回した経験に負けた**ものだった。カードの事実は公式サイトで確認できるが、デッキの動きの中でのカードの価値はユーザーの経験に正がある。スキルの手順で「聞く」項目を増やしたのはこのため。
