# 公式デッキ構築ツールの使い方

公式デッキ構築ツール(https://www.pokemon-card.com/deck/)で、デッキコードからデッキ内容を読み取る手順と、デッキを構築してデッキコードを発行する手順を定める。デッキ構築の最終アウトプットはこのツールに登録されたデッキ(デッキコード)とする(README「デッキ構築のアウトプット」)。

作業前に[公式サイト利用上の注意](site-usage-notes.md)を読むこと。カードの効果の確認は[カード情報の確認手順](card-lookup.md)に従う。

最終確認日: 2026-08-22。URL の形式、ページ構造、画面の挙動は公式サイトの実装から確認した観測結果であり、公式が保証する仕様ではない。動作しなくなっていたら、各ページを画面から操作して現在の挙動を確認し、この手順書を直す。

## ツールの全体像

| ページ | URL | 役割 |
| --- | --- | --- |
| デッキ構築 | https://www.pokemon-card.com/deck/deck.html | カードを選んでデッキを組み、レギュレーションチェックとデッキ登録を行う |
| デッキ表示 | https://www.pokemon-card.com/deck/confirm.html/deckID/{デッキコード}/ | デッキコードからデッキ内容を表示する |
| デッキカード検索 | https://www.pokemon-card.com/deck/deckSearch.php | デッキ構築ページから開く、デッキに入れるカードの検索画面 |
| 保存結果 | https://www.pokemon-card.com/deck/result.html/deckID/{デッキコード}/ | デッキ登録直後に遷移する。発行されたデッキコードを示す |

- **デッキコードの発行までログインは不要。** アカウントを使う機能は保存結果ページの「マイデッキに登録する」だけで、これはプレイヤーズクラブ(https://players.pokemon-card.com/)のログインページに遷移する(2026-08-22 に遷移先がログイン画面であることを確認)
- **マイデッキ登録はこのプロジェクトの対象外とする**(開発責任者の決定。2026-08-22)。プレイヤーズクラブの認証まで自動化に含めると難易度が大きく上がる一方、マイデッキ登録そのものはデッキコードがあれば人手でほぼワンクリックで済み、1 人あたりの登録数も新弾の発売などの節目に少しずつ増える程度で多くない。エージェントはデッキコードの発行までを担い、マイデッキ登録は人が行う
- スタンダードの対戦デッキは 60 枚([基本ルール](basic-rules.md)「デッキの規定」)。構築ページには 40 枚・30 枚デッキの選択肢もあるが、このリポジトリでは初期選択の「60枚デッキ」だけを使う

## 1. デッキコードからデッキ内容を読み取る

1. `https://www.pokemon-card.com/deck/confirm.html/deckID/{デッキコード}/` を開く
2. ページ上部に**【枚数】**(例: 60枚デッキ)と**【デッキコード】**が表示される。デッキコードが存在しない場合はカードが表示されず、「デッキコードエラー 該当するデッキコード[入力値]は見つかりません」と表示される(存在しないコードで確認)
3. カード一覧の右上の「**リスト表示**」を選ぶ。初期状態は「画像表示」で、リスト表示に切り替えるとテキストでまとめて読み取れる

リスト表示で読み取れるもの:

- カテゴリ見出し: 「ポケモン (16)」「グッズ (17)」「ポケモンのどうぐ (0)」「サポート (10)」「スタジアム (3)」「エネルギー (14)」の形式。数字は**そのカテゴリの枚数の合計**(種類数ではない)
- 各カードの名前と枚数。ポケモンにはエキスパンションマークとコレクションナンバー(例: M6 058/076)も表示される
- カード ID: カード名リンクの onclick 属性 `PCGDECK.cardDetailViewCall('50396')` の数値。カードの効果を確認するときは、この ID で詳細ページ `https://www.pokemon-card.com/card-search/details.php/card/{カード ID}/regu/XY` を開く(ID 50396 でメガレックウザex の詳細ページが開くことを確認)。以降は[カード情報の確認手順](card-lookup.md)に従う

画像表示のまま読む場合は、カードごとの小さな table 単位で、img(class: thumbsImage)の alt にカード名、src のファイル名先頭にゼロ埋め 6 桁のカード ID、同じ table 内の「N枚」表記に枚数がある。

**注意: alt のカード名には補足が付くことがある**(観測例: 「プライムキャッチャー(ACE SPEC)」)。カード名として扱うときは補足を取り除く。

## 2. デッキを構築してデッキコードを発行する

### 2-1. カードを検索して追加する

1. デッキ構築ページ(https://www.pokemon-card.com/deck/deck.html)を開く
2. 「デッキに入れるカードを検索」の検索欄に検索語を入れ、「検索」を押す。**検索結果は別ウィンドウ(デッキカード検索)で開く**
3. 検索結果のカード画像をクリックすると、構築ページの「選択されたカード」に 1 枚追加される

デッキカード検索の URL は次の形式で、直接開くこともできる(検索ボタンの実装から確認)。

```
https://www.pokemon-card.com/deck/deckSearch.php?keyword={検索語}&regulation_deck={レギュレーション}&sm_and_keyword=true
```

- regulation_deck は XY=スタンダード / BW=エクストラ / DP=殿堂 / all=すべて。構築ページの「レギュレーション」ラジオと同じ値
- keyword は[カード検索](card-lookup.md)と同じく**カード名とカードテキストの両方に部分一致**する。「基本雷エネルギー」の検索で、カードテキストに一致する別カードも並ぶことを確認。**目当てのカードかどうかは名前で確かめる**
- ヒットが無いときは「見つかりませんでした」と表示される(スタンダード指定の「ネストボール」で確認)。ここに出ないカードはそのレギュレーションのデッキに入れられないカードとして扱う

ポップアップを開けない環境(コーディングエージェントのブラウザなど)では、次の順で別タブから追加する(2026-08-22 に動作を確認)。

1. **先に構築ページの検索欄に検索語を入れて「検索」を押す。** 検索ウィンドウは開かなくてよい。この操作で構築ページがカードの受け取り監視(localStorage の PCGDECKID / PCGCARDNAME のポーリング)を始める。**監視開始前にクリックしたカードは受け取られず破棄される**
2. 別のタブでデッキカード検索の URL を開き、カードをクリックする
3. 構築ページの「選択されたカード」に追加されたことを確かめる。構築ページがバックグラウンドのタブだと、タイマーの間引きにより反映まで数秒かかることがある

検索結果のカードクリックが最終的に呼ぶのは、構築ページの関数 `PCGDECK.cardItemAppendSiteCall('{カード ID}', '{カード名}')` である(検索画面の実装から確認)。監視の起動に頼らず、構築ページでこの関数を直接実行して追加してもよい。

### 2-2. 枚数を調整する

「選択されたカード」の各カードに、枚数表示・枚数の上下ボタン・「削除」がある。上下ボタンは 1 回のクリックで 1 枚増減する。

- 同じ名前のカードは 4 枚までの制限([基本ルール](basic-rules.md)「デッキの規定」)を超える枚数も UI 上は設定できてしまう場合がある。制限に反していればレギュレーションチェックで検出される
- 基本エネルギーは枚数制限が無く、59 枚まで増やせることを確認

作業中のデッキ内容は Cookie(deck_pke / deck_gds / deck_sup / deck_sta / deck_ene。値は `{カード ID}_{枚数}_{数値}` をハイフンで連結した形式。3 番目の数値の意味は未確認)に保持され、ページを開き直すと復元される(確認済み)。同じ内容がページ内の同じ名前の hidden input にもあり、現在の選択内容を機械的に確かめる手段になる。

### 2-3. レギュレーションチェックを実行する

1. 「レギュレーションチェック」ボタンを押す(サーバー側の検証。/deck/deckRegulation.php への POST)
2. エラーが無ければ「基本ルール・すべてのレギュレーションでエラーはありませんでした デッキを保存できます」と表示され、それまで無効だった「**デッキ登録**」ボタンが押せるようになる

### 2-4. デッキ登録してデッキコードを得る

1. 「デッキ登録」ボタンを押す
2. 確認ダイアログ「デッキを保存しますか?」で OK を押す
3. 保存結果ページ `https://www.pokemon-card.com/deck/result.html/deckID/{デッキコード}/` に遷移する。**URL のこの部分が発行されたデッキコード**。ページに「デッキコードをコピーする」ボタンもある
4. 発行されたコードは、手順 1 のデッキ表示ページで読み取れることを確認する

確認ダイアログはブラウザのネイティブダイアログのため、自動化環境ではダイアログが抑止されてキャンセル扱い(confirm が false)になり、登録が実行されないことがある(使用したブラウザのコンソールに「confirm() returned false」が記録されることを確認)。登録できたかどうかは、保存結果ページへ遷移したかで判定する。

### 2-5. 操作ごとの通信量と効率の良い組み方

構築ページの各操作がサーバーと通信するかを、ページ内の resource timing で観測した(2026-08-23)。

| 操作 | サーバーとの通信 |
| --- | --- |
| 枚数の上下(手順 2-2) | 無し。ページ内の hidden input と Cookie の更新だけ |
| 既にデッキにある同じ名前のカードの追加 | 無し。デッキ内の既存の印刷のエントリに合流して枚数が増える |
| デッキに無いカードの追加 | サムネイル取得の GET(/deck/deckThumbsImage.php?cardID=...)を観測。2 回目以降はキャッシュが効くとみられる |
| レギュレーションチェック(手順 2-3) | 有り(POST) |
| デッキ登録(手順 2-4) | 有り(POST) |

サーバーへの配慮([公式サイト利用上の注意](site-usage-notes.md))が必要なのはカード検索・レギュレーションチェック・デッキ登録で、選択済みカードの出し入れ自体は速く操作してよい。この観測に基づく効率の良い組み方は次の通り。

1. カード 1 種につき、追加(手順 2-1)を 1 回だけ行う
2. 枚数は枚数ボタン(実体は `PCGDECK.cardCntChange`)で合わせる。通信が無いため間隔を空ける必要はない
3. レギュレーションチェックとデッキ登録は各 1 回

自動化での注意: 同じカードの追加を非同期ループでまとめて投げると、実行環境側がタイムアウトしてもページ内のループは動き続け、あとから枚数が増えて集計が狂う(60 枚に揃えたあとで枚数が増える事象として確認)。上記 1〜2 の方式ならループ自体が不要になる。

## 3. 既存デッキを基に改良する

デッキ表示ページの「**このデッキから新しいデッキを作る**」ボタンで、そのデッキを初期状態にした構築ページが開く。実体は次の URL への遷移で、直接開いてもよい(ボタンの実装から確認)。

```
https://www.pokemon-card.com/deck/deck.html?deckID={デッキコード}
```

- 60 枚がカテゴリ別に読み込まれた状態から、手順 2-1〜2-4 と同じ流れで編集・チェック・登録する
- 登録すると**新しいデッキコードが発行される。元のデッキコードのデッキはそのまま残る**(1 枚入れ替えて登録し、新旧両方のコードが別内容で表示できることを確認)

## 4. デッキコードの扱い

- デッキコードは登録のたびに発行される識別子で、**コードを知っていれば誰でもデッキ表示ページで内容を閲覧できる**
- 登録したデッキがいつまで保存されるかの規定は確認できていない(未確認)
- **動作確認のためのテスト登録は最小限にする。** 登録は公式サーバーにデッキを保存する操作であり、確認のたびに乱発しない。読み取り手順の検証には既存のデッキコードを使う

## 5. 印刷(レアリティ・再録)違いの扱い

同じ名前のカードには印刷ごとに別のカード ID がある([カード情報の確認手順](card-lookup.md)「同じ名前のカードと複数のカード ID」)。構築ページでは、検索結果でクリックした印刷のカード ID がデッキに入り、デッキコードにもその ID が記録される。つまり**デッキ登録は印刷(カード ID)単位**で行われる。

- 書いてあることが同じ、同じ名前のカード(印刷違い)は、レアリティが違ってもルール上の違いは無い。公式 Q&A で確認(検索結果 URL: https://www.pokemon-card.com/rules/faq/search.php?freeword=%E3%82%A4%E3%83%A9%E3%82%B9%E3%83%88%20%E9%81%95%E3%81%86&regulation_faq_main_item1=all 、該当 Q&A の要旨: キラキラのカードとそうでないカードの違いを問う質問に、カードに書いてあることが同じならルール上の違いは無いと回答。2026-08-23 確認)
- 公式大会でも、同じ名前で同じ内容のカードはレアリティ・イラスト・エキスパンションマークが違っても同じカードとして扱われ、デッキ登録した印刷と手元で使う印刷が違っても問題ない(出典: 【公式】ポケモンカードチャンネルの動画「【初心者向け】これでバッチリ！大会参加の心得【ポケカ/ポケモンカード】」2024-09-17 公開、該当箇所 8:12 付近 https://www.youtube.com/watch?v=fBpX5yrMFmo 。2026-08-23 確認)
- 使う印刷にこだわりがあるユーザー(手持ちのカードと同じ印刷で登録したい、レアリティの高い印刷で登録したい等)には、希望の印刷のカード ID を確認し、その ID で登録する
- **印刷を指定したいカードは、最初からその印刷の ID で追加する。** 同じ名前のカードの別の印刷の ID を追加しても、新しいエントリにはならず、既にデッキにある印刷に合流して枚数だけが増える(印刷 50461 のハイパーボールがあるデッキに印刷 49367 を追加したとき、50461 の枚数が増えることを 2026-08-23 に確認)
